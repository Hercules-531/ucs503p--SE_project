01 · Authentication

Send an API key as a header

For the shell example below, set BHARATOS_URL to the base address printed at startup, without a trailing slash.

{% if demo_key %} 
curl "$BHARATOS_URL/api/v1/schemes" \
  -H "X-API-Key: {{ demo_key }}"

This public key is available only in the in-memory prototype.

{% else %} 
curl "$BHARATOS_URL/api/v1/schemes" \
  -H "X-API-Key: YOUR_PERSONAL_KEY"

Register and sign in on the developer page to create a personal key. Keys are displayed once and can be revoked.

{% endif %}

Developer account endpoints use an eight-hour session token in the Authorization: Bearer header. If configured, per-key limits return 429 and Retry-After.

02 · Endpoints

Current API surface

MethodPathPurpose
GET/api/v1/schemesSearch and filter scheme snapshots.
GET/api/v1/schemes/{scheme_id}Retrieve one canonical record.
GET/api/v1/locations/pincode/{pincode}Resolve one prototype PIN-code record.

Scheme-list query parameters: q, category, state, and audience. Optionally add limit (1–100) and offset (starting at 0) to page through matches in scheme-ID order. The response reports page size in result_count and all matching records in total_count. Offsets require a limit. Changes between requests can shift pages; without a limit, the existing complete-list behavior remains.

meta.uncertain_excluded_count counts potentially relevant records excluded because a selected state or audience is unspecified. Set include_unknown=true to include those records; meta.uncertain_included_count then reports their total. Both counts cover the full matching set, not only the current page. Inclusion is not an eligibility decision.

Account registration, sign-in, key management and usage endpoints are listed in the interactive reference. The OpenAPI JSON can be used by client generators.

03 · Contract

Standard success and error envelopes

Success

{
  "data": [...],
  "meta": {
    "api_version": "v1",
    "environment": "prototype",
    "source": "...",
    "last_verified": "2026-09-09",
    "generated_at": "..."
  }
}

Error

{
  "error": {
    "code": "INVALID_API_KEY",
    "message": "...",
    "request_id": "..."
  }
}

For a scheme list, last_verified is the oldest verification date among the returned records. If a response page is empty, including when its offset is beyond the matches, it reflects the available catalogue. It is null for an empty catalogue or when a relevant record has no verification date. A third-party mirror's snapshot_date is its commit date, not an official verification date.
