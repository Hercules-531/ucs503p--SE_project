# Local HTTPS verification — 8 November 2026

An isolated Compose project started PostgreSQL, Redis, the migrated application and the optional
Caddy TLS proxy on separate localhost ports. The proxy generated a certificate for `localhost`
using its internal development CA; automatic installation into the host trust store was disabled.

A Python TLS client supplied with the exported public root certificate successfully verified the
certificate chain and hostname and retrieved `/health/ready`, which reported PostgreSQL and Redis
as ready. A client using the unmodified system trust store rejected the untrusted local CA, as
expected. Windows curl with its Schannel backend reported that revocation status was unknown when
the local root was supplied; the documented Python verification method succeeded without changing
the system trust store.

The isolated containers, test PostgreSQL volume and Caddy private CA volumes were removed after
the drill. A copy of the test CA's public root remains in the ignored local `tmp` directory. No
host trust settings were changed. This test does not validate public DNS, public certificates,
internet exposure, external proxy configuration or production security.
